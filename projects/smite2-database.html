Smite 2 Overlay and Tracker

A always-on-top desktop overlay for Smite 2 that tracks matchup winrates and KDA between gods, backed by a MySQL database of logged matches.

Project Overview

This project is a small, frameless PyQt5 overlay that stays pinned to the corner of the screen while playing Smite 2. It lets me pick my god, an enemy god, and a role from dropdowns, and instantly shows the historical winrate and KDA for that specific matchup, pulled live from a MySQL database of logged matches.

Beyond the live matchup lookup, the overlay has two other screens: an "Add Match" form for logging a completed game's role, gods, kills/deaths/assists, game time, and win/loss, and a "View Matchups" window that queries the database for the top 5 best and worst matchups for the selected god and role, ranked by winrate.

Key Features

  • Always-on-top, frameless overlay that stays out of the way during a match
  • God, enemy god, and role dropdowns that instantly update the displayed stats
  • Live winrate and KDA lookup for a specific god-vs-god-vs-role matchup
  • Add Match form for logging date, gamemode, role, gods, kills/deaths/assists, game time, and win/loss
  • View Matchups window showing the top 5 best and worst matchups by winrate, with a minimum-games threshold to avoid small sample sizes
  • All stats calculated directly from SQL queries against a MySQL database rather than pre-computed

Technologies Used

Language: Python

Interface: PyQt5 desktop overlay

Data: MySQL database (smite_stats), with gods and matches tables

Tools: Python, MySQL, Git, GitHub

Challenges

Getting the overlay to actually behave like an overlay — frameless, always-on-top, and positioned so it doesn't block the game — took some tuning of PyQt5's window flags and geometry rather than just building a normal application window.

Writing the matchup queries also took care, since winrate and KDA needed to be calculated correctly per god, per enemy god, and per role, while the best/worst matchups query additionally needed a minimum-games threshold so a single lucky or unlucky game didn't dominate the results.

All data has to be pulled by hand currently. For Smite 2 there is no official or even unoffical way to pull full games with stats in one go There is no way to pull this data in the game files, and website that do have trackers do not have offical APIs or API keys to allow me to pull them from tracker websites.

What I Learned

This project strengthened my SQL skills, especially writing aggregate queries with subqueries, joins, and HAVING clauses to turn raw match logs into useful stats like winrate and KDA on the fly.

It also gave me practical experience with PyQt5 beyond a standard window — building a persistent overlay, wiring up multiple secondary windows, and keeping the interface responsive to live dropdown changes.
