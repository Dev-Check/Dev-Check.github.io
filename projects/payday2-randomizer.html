Payday Randomizer

A desktop GUI application built for the game Payday 2 that lets players pick which DLC they own and then generates a fully randomized loadout — primary weapon, secondary weapon, melee weapon, gadget, throwable, perk deck, and heist — pulled from a database of in-game items.

Project Overview

Payday Randomizer is a Python GUI application that solves a simple problem for Payday 2 players: deciding what to bring on a heist. Instead of manually picking a loadout, the app lets the user select which DLC packs they own, then randomly generates a full loadout using only items from content they actually have access to.

The item data — weapons, gadgets, throwables, perk decks, and heists — is stored in a database rather than hard-coded into the app, which meant designing a schema up front (an ERD) to properly separate items by category and by which DLC they belong to before writing the randomization logic on top of it.

Key Features

  • DLC selection so results only include content the user actually owns
  • Randomized primary weapon, secondary weapon, and melee weapon
  • Randomized gadget, throwable, and perk deck
  • Randomized heist selection
  • Item data stored in and pulled from a database rather than hard-coded
  • Desktop GUI built in Python

Technologies Used

Language: Python

Interface: Desktop GUI application

Data: Relational database, designed from an ERD

Tools: Python, Git, GitHub

Challenges

Designing the database schema before writing any of the randomization code was a different workflow than I was used to. Getting the ERD right — properly linking weapons, gear, and heists to the correct DLC packs — took some iteration before the relationships actually supported clean queries.

Building the GUI itself was also a learning curve, since it meant thinking through the user's flow (selecting DLC, triggering randomization, displaying results) rather than just running everything through a terminal.

What I Learned

This project gave me hands-on experience designing a database schema from scratch, starting with an ERD and working forward into actual tables and queries, rather than adapting an existing structure.

It also strengthened my Python GUI development skills and my ability to connect a front-end interface to a backing database in a way that stays organized as more features get added.
