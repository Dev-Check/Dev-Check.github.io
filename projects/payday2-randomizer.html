Payday Randomizer

A desktop GUI application built for the game Payday 2 that lets players pick which DLC they own and then generates a fully randomized loadout — primary weapon, secondary weapon, melee weapon, gadget, throwable, perk deck, and heist — pulled from a database of in-game items.

Project Overview

Payday Randomizer is a Python GUI application that solves a simple problem for Payday 2 players: deciding what to bring on a heist. Instead of manually picking a loadout, the app lets the user select which DLC packs they own, then randomly generates a full loadout using only items from content they actually have access to.

The item data — weapons, armor, gear, throwables, perk decks, and heists — lives in a MySQL database rather than being hard-coded into the app, which meant designing a schema up front (an ERD) to properly separate items by category and by which DLC they belong to before writing the randomization logic on top of it.

The GUI itself, built with Tkinter, includes a slot-machine style roll: hitting the Roll button or spacebar spins through random results for about two seconds before landing on the final loadout. A separate "Manage DLC" window lets the user check off which DLC packs they own, with Select All / Select None shortcuts, and saves those choices back to the database.

Key Features

  • Manage DLC window with checkboxes, plus Select All / Select None, to control which content the randomizer can pull from
  • Randomized primary weapon, secondary weapon, melee weapon, armor, deployable equipment, perk deck, and throwable
  • Randomized heist with a Loud or Stealth mode, depending on the heist's supported styles
  • Perk-throwable synergy — certain perk decks (like Leech or Hacker) automatically pair with their matching throwable instead of rolling one at random
  • Attachment rules tied to whether the rolled heist came up Loud or Stealth
  • All item data pulled live from a MySQL database rather than hard-coded

Technologies Used

Language: Python

Interface: Desktop GUI built with Tkinter

Data: MySQL database, designed from an ERD, with tables for weapons, armor, equipment, melee, perk decks, throwables, heists, and DLC

Tools: Python, MySQL, Git, GitHub

Challenges

Handling edge cases in the randomization logic took extra thought — some perk decks (like Leech or Hacker) needed to force a specific matching throwable instead of a random one, and attachment rules needed to change depending on whether the rolled heist landed as Loud or Stealth.

Building the Tkinter GUI was also a learning curve, especially getting the slot-machine-style rolling animation to run smoothly on a timer without freezing the rest of the interface, and building a separate scrollable DLC-management window that stayed in sync with the database.

Populating the database itself was one of the most time-consuming parts of the whole project. I couldn't find any existing CSV files listing every Payday 2 weapon, piece of gear, perk deck, and heist along with its DLC, so all of that data had to be entered by hand from scratch before the randomizer had anything to actually pull from.

What I Learned

This project gave me hands-on experience designing a database schema from scratch, starting with an ERD and working forward into actual tables and queries, rather than adapting an existing structure.

It also strengthened my Python GUI development skills and my ability to connect a front-end interface to a backing database in a way that stays organized as more features get added.
