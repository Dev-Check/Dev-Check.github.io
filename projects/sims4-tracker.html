Sims 4 Challenge Tracker

A full-stack Android application for The Sims 4 players to organize and track progress through legacy and generational challenges — browsing challenges, viewing generation requirements, and checking off goals like aspirations, traits, careers, and milestones.

Project Overview

This is a full-stack Android app built in Java through Android Studio. The app fetches challenge data from a Flask server I built, which is backed by a MongoDB database of legacy/generational Sims 4 challenges — each challenge broken down into generations, and each generation into its own aspiration, career, traits, and list of goals.

On the main screen, the app pulls the full list of challenges from the server and displays them in a list. Tapping a challenge opens its first generation's details, with goals shown as a checkable list. From there you can page forward and backward between generations, and jump back to the main challenge list at any time.

Key Features

  • Browse all available Sims 4 legacy/generational challenges
  • Challenge data fetched live from a Flask server backed by MongoDB
  • Per-generation breakdown of aspiration, career, and traits
  • Checkable goal list for tracking progress within a generation
  • Forward/backward navigation between a challenge's generations
  • Quick navigation back to the main challenge list

Technologies Used

Language: Java

Platform: Android (Android Studio)

Backend: Flask server (Python), serving data pulled from MongoDB

Tools: Android Studio, Python, MongoDB, Git, GitHub

Challenges

Structuring the data so it made sense on both ends was one of the bigger challenges — each Sims 4 challenge needed to be broken down into generations, each with its own aspiration, career, traits, and goals, and that structure had to hold up cleanly through MongoDB, the Flask server, and the JSON parsing on the Android side.

Getting the Android app to talk to the Flask server reliably — parsing the returned JSON, handling nested arrays of generations and goals, and passing that data between activities — took some real debugging, especially around edge cases like missing fields in the JSON.

What I Learned

This project gave me real full-stack experience — designing how data should be modeled in MongoDB, exposing it through a Flask API, and consuming it from an Android client, rather than working on just one layer of an application.

It also strengthened my Android development skills, particularly around passing structured data between activities, working with ListViews and custom adapters, and handling asynchronous network requests safely on a background thread.
